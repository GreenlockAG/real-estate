Build Brief: “Risk Monitoring” — Start Simple, Data First

Goal:
Implement a minimal, evolvable data layer to capture user inputs for a 4-part risk workflow (Setup → Parameter Pack → Analysis → Governance). Replit can choose stack and UI. Prioritize clean schema, versioning, auditability, and easy future extension.

Core Objects (neutral, framework-agnostic)

Organization: container for tenants and users.

User: role-based access (admin/editor/viewer).

Portfolio: belongs to Organization; base currency, AUM.

Sleeve: normalized sub-allocations for a Portfolio.

PrivateExposure: % PE, Private Credit, Core Infra; reporting lag; smoothing.

GovernanceConstraint: max DD %, horizon months, notes.

LiquidityNeeds: next-12m calls, op cash, reserve rule.

RebalancingPolicy: band (pp) and frequency.

FXOverlay: hedge ratios and optional CHF buffer.

RiskParameterPack (versioned): vols/returns/hedge effectiveness; CorrelationMatrix; StressScenario.

SimulationRun: references a ParameterPack; stores inputs snapshot (immutable).

SimulationResultMetric: values (VaR/CVaR/DD/etc.) by scope (portfolio/sleeve).

ScenarioResult: per stress scenario outcomes.

GovernanceReview: compliance vs constraints + recommendations.

Document: stored reports/memos (URI or blob).

AuditLog: before/after diffs for any mutation.

Minimal Enumerations

Sleeve.type: GROWTH | CREDIT | DURATION | TIPS | CTA | COMMODITIES | DIVERSIFIERS | REAL_ASSETS | LIQUIDITY

RebalancingPolicy.frequency: MONTHLY | QUARTERLY | ANNUAL

RiskParameterItem.kind: VOL | RETURN | HEDGE_EFF | OTHER

SimulationRun.engine: MONTE_CARLO | HISTORICAL | STRESS_ONLY

SimulationResultMetric.metric: VAR | CVAR | MAX_DD | DD_PROB | VOL | LIQ_BUFFER_DAYS

StressScenario.category: MACRO | RATE | CREDIT | COMMODITY | FX | CUSTOM

Invariants & Validation (apply regardless of storage)

Sleeves: must include all 9 types; enforce uniqueness (portfolio, type).

Weights: warn if total deviates from 100% by >1pp (store warning on save).

Governance: 0 ≤ maxDdPct ≤ 100, horizonMonths ∈ {12,18,24,36}.

Liquidity: require at least one of reserveMultiple or reserveM.

FX hedge ratios: each in [0,100].

Correlation matrix: square, symmetric, unit diagonal, entries in [-1,1].

Parameter pack version: unique per portfolio.

Simulation run snapshot: immutable copy of portfolio + parameter pack at run time.

Minimal Actions (API or scripts—Replit chooses)

Create Portfolio (Part 1): persist all inputs atomically; write AuditLog.

Create Parameter Pack (Part 2): validate matrix/scenarios; enforce version uniqueness.

Create Simulation Run (Part 3): capture immutable inputsSnapshot.

Create Governance Review (Part 4): mark compliant using a stub rule (e.g., MAX_DD ≤ maxDdPct).

Get Portfolio Summary: return sleeves, constraints, liquidity, fx overlay, latest pack version.

Seed Data (simple)

One Organization, two Users.

One Portfolio with all 9 sleeves (weights sum ~100%).

One ParameterPack version=1 with small 9×9 corr matrix and 2 stress scenarios.

One SimulationRun with a handful of metrics.

One GovernanceReview (compliant).

Acceptance (light, stack-agnostic)

✅ Part 1 save is transactional and produces an audit record.

✅ Parameter pack with invalid matrix fails validation with a clear message.

✅ Simulation run stores a full inputsSnapshot that does not change if the portfolio later changes.

✅ Governance review computes a boolean compliant against stored results and constraint.

✅ A lightweight “export” endpoint/command can dump a portfolio (Part 1) as JSON.

Future-proofing (don’t implement now)

Role checks (admin/editor/viewer).

Import/export CSV for sleeves.

Blob storage for Documents (memos, reports).

Indexes for common lookups (by org, portfolio, version, run date).

Instruction to Replit: Choose the simplest path (files, SQLite, or a doc store) and scaffold only what’s needed to persist and retrieve these objects plus validations and seed data. No UI requirements; a minimal CLI or endpoints are fine.
